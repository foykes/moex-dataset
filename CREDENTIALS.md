# Где заполнить учётные данные

Для исправления кода и обычной работы с GitHub новые логины и пароли сейчас не нужны.
GitHub CLI уже авторизован как `foykes`, права чтения и публикации веток проверены.
Сборщики MOEX и Доход.ру в текущем коде отправляют запросы без учётных данных.
Расчёт индикаторов и изолированные тесты также не требуют внешних аккаунтов.

Реквизиты требуются для публикации результатов через `upload.py`:

| Назначение | Что требуется | Куда положить |
| --- | --- | --- |
| FTP | Адрес FTP-сервера, FTP-логин и FTP-пароль | `secrets/moex.foykes.com.json` |
| Google Sheets | JSON-ключ сервисного аккаунта и доступ этого аккаунта к таблице | `secrets/python-304621-1e403209f05f.json` |

На момент подготовки настоящих файлов в локальной папке проекта и соседней папке
`../secrets` не обнаружено. Созданы только заготовки, не действующие учётные данные.
Пока мы работаем с кодом, их можно оставить незаполненными. Для полного запуска
`main.py` понадобятся оба набора: его этап публикации запускает FTP и Google Sheets.

## 1. FTP: заменить логин и пароль

Откройте `secrets/moex.foykes.com.json`. В нём уже есть три поля:

```json
{
  "domain": "moex.foykes.com",
  "username": "REPLACE_WITH_FTP_LOGIN",
  "password": "REPLACE_WITH_FTP_PASSWORD"
}
```

- `domain`: настоящий адрес FTP-сервера из настроек хостинга. `moex.foykes.com`
  подставлен по имени файла и адресу публикации; фактический FTP-хост нужно подтвердить.
  Адрес вводится без `ftp://`, `https://`, пути и номера порта.
- `username`: замените `REPLACE_WITH_FTP_LOGIN` на логин учётной записи FTP.
- `password`: замените `REPLACE_WITH_FTP_PASSWORD` на пароль этой учётной записи.

Нужны реквизиты FTP, а не пароль от панели управления хостингом.
Текущий код использует обычный FTP на порту 21; SFTP, FTPS и произвольный порт
не настраиваются этим JSON. Если хостинг предоставляет другой протокол или порт,
сначала потребуется адаптировать подключение.

Сохраните корректный JSON: имена полей не меняйте, строки оставьте в двойных кавычках.
Кавычка внутри пароля записывается как `\"`, обратная косая черта — как `\\`.
Комментарии в JSON добавлять нельзя. У FTP-аккаунта должны быть права записи;
код также использует каталоги `dividends` и `ticker_lists` относительно корня FTP-сеанса.

## 2. Google Sheets: заменить файл целиком

Пароль от вашего Google-аккаунта не нужен. Код вызывает
`pygsheets.authorize(service_file=...)` и ожидает JSON-ключ сервисного аккаунта.
Подключение Google Drive в приложении само по себе не заменяет этот файл для Python.
[Документация авторизации pygsheets](https://pygsheets.readthedocs.io/en/stable/authorization.html).

Если рабочий JSON-ключ сохранился с прежнего устройства, скопируйте его в
`secrets/python-304621-1e403209f05f.json`, заменив заготовку целиком.
Если ключа нет, получите его через Google Cloud:

1. Выберите нужный проект в [Google Cloud Console](https://console.cloud.google.com/).
2. Включите **Google Sheets API** и **Google Drive API**, необходимые pygsheets.
3. В разделе **IAM & Admin → Service Accounts** выберите подходящий сервисный аккаунт
   или создайте его, если он отсутствует.
4. Откройте **Keys → Add key → Create new key**, выберите **JSON** и скачайте файл.
5. Замените нашу заготовку этим скачанным файлом целиком. Сохраните точное имя
   `python-304621-1e403209f05f.json`: оно пока зафиксировано в коде.

Порядок создания ключа и формат JSON описаны в
[документации Google Cloud](https://docs.cloud.google.com/iam/docs/keys-create-delete).
Если создание ключей запрещено политикой вашего проекта, этот способ авторизации
пока недоступен; не пытайтесь заполнять `private_key` вручную.
Имя файла в коде не требует использовать именно проект `python-304621`:
подойдёт действующий сервисный аккаунт с нужным доступом.

Откройте целевую таблицу и предоставьте доступ **Редактор** адресу из поля
`client_email` скачанного JSON. Это адрес сервисного аккаунта, не ваш личный email.
[Как предоставить доступ к файлу](https://support.google.com/drive/answer/2494822?hl=ru).
В коде сейчас указана [эта таблица](https://docs.google.com/spreadsheets/d/1HXXoxcDVqIrWN6QEg5ij88AxcNAKT-G-xm2UTUfQe1Q/edit).
Если нужна другая таблица, потребуется отдельно обновить URL в коде и связанной
ноутбук-паре: добавление нового поля в JSON этот адрес не изменит.

## После заполнения

Сохраняйте файлы локально, с расширением `.json`, а не `.json.txt`.
Не вписывайте реальные логины, пароли и ключи в эту инструкцию или другие
отслеживаемые Git файлы. Папка `secrets/` исключена из Git существующим правилом
в `.gitignore`; не используйте `git add -f` для её содержимого.

Эти файлы доступны локальным Python-процессам и следующим чатам, работающим
с этой же папкой проекта. Git не переносит их в другой клон или worktree:
для такого рабочего каталога локальные файлы надо подготовить отдельно.

В этой Windows-папке расположение заготовок совпадает с путями, вычисляемыми
текущим `upload.py`. Его выражение `current_path.rsplit("/", 1)` зависит от
разделителя пути: на Linux/macOS оно ищет `../secrets` вместо `secrets/` внутри
проекта. Перед публикацией на другой системе нужно согласовать расположение
или исправить эту логику пути.

После заполнения достаточно написать в чат «файлы заполнены». Проверять будем
наличие полей и формат, без вывода паролей и приватных ключей. Работоспособность
учётных данных и доступ к таблице требуют отдельной проверки подключения.

Не запускайте `main.py` или `upload.py` просто для проверки реквизитов:
они публикуют файлы, а Google-этап сначала очищает первый лист целевой таблицы.
